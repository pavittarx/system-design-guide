<Recap>

- **Async is a choice about waiting, not about work.** Do the essential part while the user waits, queue the rest, and answer them now.

- **A queue is a shock absorber.** Bursty traffic in, a steady rate out. Put a limit on its length, or the buffer becomes the outage.

- **Work queue: one consumer gets each message. Pub/sub: every subscriber does.** Sharing out tasks versus announcing events.

- **At-least-once is the real default.** End-to-end exactly-once is a story; at-least-once plus duplicates that do nothing is how it's actually built.

- **"Check, then act" is a race.** Two consumers can both check before either acts. Claim the message ID with one atomic insert, and only the winner does the work.

- **A claim needs a status and an expiry**, or a crash mid-work leaves a message marked done that never ran.

- **For outside side effects, send the provider an idempotency key.** If the work can't go in your transaction, let whoever owns it spot the repeat.

- **A visibility timeout below your p99 means the same job runs twice at once**, and if the job is slow for everyone, it's redelivered forever. Extend the deadline for long jobs; cap redeliveries.

- **Order holds only within a partition, and a partition is a queue of one.** Working in parallel and keeping strict order are mutually exclusive: pick.

- **Never write to the database and the broker as two steps.** Put the event in an outbox table in the same transaction, or read it from the database's change log.

- **Send a pointer, not the payload.** A claim check keeps messages small and under the broker's size limit.

- **Deploys are rolling, so message formats must only grow.** Ignore unknown fields, add optional ones, never change what a field means.

- **Alert on lag and whether it's rising, not on depth.** Deep and draining is fine; shallow and growing is not.

- **An unwatched DLQ is a landfill.** Alert on arrivals and rehearse putting messages back.

- **You need N > A / C consumers, always.** Without capacity above the arrival rate, a backlog never drains.

</Recap>
